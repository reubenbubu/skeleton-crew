- #21, compose project names colliding across checkouts, is done: every name starts with `crew-<id>-`, where `<id>` is the first 8 hex digits of the SHA-256 of the main checkout's absolute path, as `git worktree list` reports it. The names are `crew-<id>-<n>`, `crew-<id>-<n>-gate` and `crew-<id>-doctor` (`internal/compose`). `crew env`, `crew run` and `crew commit` find the main checkout from the Dev's worktree (`ticketHere`); the gate, `crew merge`, `crew doctor` and the leftover removal already had it. `TestProjectNamesSeparateCheckouts` covers AC1 and AC3; the CLI tests check every command's names. The containers tests were not rerun: they name their own projects.
- #22, merging under an older approval, is done. `crew commit` refuses outside `4:in-progress` and `4:review-rejected` (`ticket.Committable`). `crew review` refuses unless the PR head has a successful `crew/gate` status created since the ticket last got `stage:4:in-progress` (`ticket.submitted`). `crew merge` reads the approved commit, the `CommitID` of the newest `approved` crew review (`ticket.Approved`), before it moves the stage. When the branch head differs, `rebaseOf` in `internal/cli/merge.go` rebases the approved commit onto the head's merge base with `origin/main` and requires the same trees, commit for commit. The DM rule says how to handle a `not-approved` refusal: force-push the branch back to the approved commit. Known false refusals, both recoverable that way: `main` rewritten after a merge pushed its rebase, and a commit at `4:review-rejected` followed by an appeal (`not-submitted`).
- `AGENTS.md` now asks agents working on Skeleton Crew to use the codebase-memory MCP server in the main checkout and in every worktree, indexing a worktree on its own path first. It applies to this repository only; the rules `crew` ships stay harness-neutral.
